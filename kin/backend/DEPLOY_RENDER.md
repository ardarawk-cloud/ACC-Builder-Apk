# KIN Phase 1A — Render Alpha Deploy

The repository root `render.yaml` is the deployment authority for the first cloud alpha.

## What it creates

- `kin-api-alpha` — Docker web service in Singapore
- `kin-postgres-alpha` — PostgreSQL in Singapore
- `KIN_ENVIRONMENT=production`
- `KIN_DATABASE_URL` wired from the Render Postgres connection string
- `KIN_JWT_SECRET` generated by Render
- `/health` health check
- auto deploy only after GitHub CI checks pass

## Deploy

Use the branch-specific Deploy to Render URL:

https://render.com/deploy?repo=https%3A%2F%2Fgithub.com%2Fardarawk-cloud%2FACC-Builder-Apk%2Ftree%2Ffeat%2Fkin-foundation-v1

Review the two resources and approve the Blueprint in the Render workspace.

After provisioning, record the HTTPS service URL, for example `https://kin-api-alpha.onrender.com`.

Do not set Android `KIN_API_BASE_URL` until `/health` on that exact deployment returns success.

## Alpha-only limitation

The Blueprint intentionally uses Render free plans for the first two-device validation. Free Render PostgreSQL expires after 30 days, is limited to 1 GB, and does not provide production-grade durability/backups. It is acceptable only for this internal validation gate.

Before any long-lived/public alpha, move the database to a non-expiring paid Postgres plan or another persistent managed PostgreSQL provider and re-run the same verification sequence.

## Verification order

1. Render Blueprint reports both resources healthy.
2. `GET <service-url>/health` succeeds over HTTPS.
3. Configure Android `KIN_API_BASE_URL=<service-url>/`.
4. Build/sign the stable dev APK.
5. Register a new account on HP A.
6. Restart the app and verify encrypted session restoration.
7. Login to the same account on HP B.
8. Edit profile on one device and verify `/v1/me` sync on the other.

Do not merge PR #15 or claim cloud-live until these checks are complete.
